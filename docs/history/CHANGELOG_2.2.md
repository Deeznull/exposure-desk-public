# Exposure Desk 2.2.0-rc.1

Built on the existing 2.1 release candidate, preserving its dependencies and project data. Older 2.0 attachments did not contain the reported textBytes/frontier fields and were not used to replace the newer workspace. The stale instance registry could not identify the user's previous launch folder. Future registrations, Diagnostics and reports include build metadata; a different running build produces a launcher warning.

Error bodies and headers remain inspectable at 401/403/404/5xx. HTTP refusal, authentication indicators, suspected bot indicators, network failure, policy rejection and unavailable browser inspection remain distinct. Password forms do not stop public script discovery. Application resources precede deployment probes; base URLs and meaningful query order/escaping are preserved. Nuxt/Astro references join representative Next/Vite/Webpack coverage; maps retain embedded virtual sources.

The final HTTP framework fixture exposed numeric Webpack table keys causing detector parsing exceptions. Numeric property names now remain safe to inspect. Transport distinguishes decoded-but-detector-failed text from invalid text encoding, retains valid decoded content for linked-resource discovery and records explicit header/body analysis failures.

Both offline and website rules now analyze bounded decoded views, retaining original representation and separate locations. Enumeration is bounded to 250 ms per transform pass, 128 views, three levels and 128 KiB expanded text; tokens and literal fragments have smaller bounds. Time/count/size limits remain coverage gaps. Static analysis does not execute downloaded code. Native regex continuations cannot silently shorten complete values; HTML comment delimiters remain valid boundaries. Azure AI, UUID Postmark contexts, Resend, supported signed URLs and Slack capability links are added. Config/debug/stack/unsigned endpoint observations remain distinct from credential evidence. Capability links are inspected locally and never redeemed.

Coverage groups, explicit analysis statuses, HTTP/error counters, entry-point sufficiency, planned deployment checks, safe request-header names and static/browser status comparisons explain what was inspected. A comparison of header names is evidence, not a causal diagnosis. A drained frontier does not establish full-site coverage. Owner-authorized robots auditing and selected read-only browser URLs are explicit options. An excluded exact origin can be added to the next configuration through a deliberate approval control.

Successful committed documents retain bounded runtime inspection when DOM readiness times out. The timeout remains an incomplete gap, and pending routed scripts finish before scrolling. An actual deferred-script fixture verifies available runtime configuration without claiming that the whole application loaded.

Ad-hoc scans now retain redacted progress/history in protected storage; interrupted records recover as incomplete. Stale IDs return actionable information and clear the selected UI state. Reveals, copy and full-secret local exports remain explicit; routine UI/history/logs/reports stay masked. Vault, correlation, queues, schedules, custom RE2 rules, cancellation and checkpoint workflows are retained.

Full-pipeline Diagnostics is separate from the demo. Its 17 nonfunctional local fixtures cover HTML, base/login scripts, lazy modules, JSON, headers, virtual map sources, 403 bodies, gzip, an encoded Gitleaks-only secret, runtime globals, fresh storage, frames, selected navigation and scrolling. It verifies anonymous cookies, no getter calls and no credential/capability/destructive/unapproved traffic. Missing browser or detector execution is a failure. The fixture deliberately retains incomplete coverage for refusals and unknown proxy traffic; this is compatible with passing all expected self-test assertions.

See TEST_RESULTS.md for actual final runs and limits; coverage-registry.json and benchmark results provide per-family/per-fixture evidence. Windows remains a candidate: Linux, source bootstrap and broader enterprise policy environments are unverified. No new credential validation, exploitation, balance checks, purchases, uploads or provider messages are introduced.
