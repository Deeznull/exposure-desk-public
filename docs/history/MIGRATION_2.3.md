# Upgrade and operational limits

Stop an existing Exposure Desk instance before launching the extracted 2.3 Windows candidate. The launcher exposes the build identity and warns if it finds a different running build. Existing operator-owned project/history/vault storage and correlation keys are reused; no destructive data migration. New optional settings receive defaults when loading old projects. Prior archives remain available for rollback; do not overwrite the data folder with package contents.

External anonymous mode remains the default. Constant reconstruction defaults on. Debugger capture defaults on when browser inspection is selected. Exact history stale-asset replay defaults off; owner manifest URLs can be supplied explicitly. All stale URLs pass current scope, rate, method, credential and address checks. API descriptions are evidence only. No broad filename search or provider credential redemption.

Optional CLI: `artifacts --directory OWNER_BUILD_FOLDER --output reports/local-artifacts.json` inspects at most 128 text files and 16 MiB, with 4 MiB retained per file. It skips links, .git, caches and dependencies, makes no network requests, labels every occurrence local-only, and never promotes local material to public exposure. Explicit `--full-secrets` retains the existing protected local export policy. Public deployment log/backup probes retain at most 128 KiB per response.

Advanced settings can disable semantic analysis or debugger capture, set exact stale URLs, and enable replay from the last three saved project scans. Disabled channels remain visible as gaps. Routine findings and reports are masked; deliberate reveal/copy and local full-secret exports remain available. Raw captured code is memory-only and not added to redacted history. Full finding representations can be saved only through the existing explicit vault workflow.

Static analysis limits: 100 modules, 1 MiB per complete module, 16 MiB source graph, 128 MiB worker heap, 2.5 s worker lifetime, 1.6 s propagation deadline, 120000 operations, 32 value recursion, 512 views and 1 MiB expanded values. Functions, arbitrary calls, dynamic imports/specifiers, runtime branches, getters, executable obfuscation and unresolvable cycles are unknown. Import-map scopes/prefix mappings and separate process debugger targets are not supported. Complete-document analyzers do not claim coverage for truncated resources. Formats over 16 KiB are outside window-overlap guarantees.

Scans always refetch within limits; no incremental HTTP analysis cache is added. A 304 without a trustworthy cached body is incomplete. Comparisons require matching scope/settings/rules and sufficient resource coverage; disappearance does not establish revocation. Owner build-artifact mode remains separate from public reachability.

Acorn does not parse TypeScript type annotations or JSX. Those files retain text/decoded detection while semantic parsing records a failure. Website context inspection of reconstructed views has a separate 2 s deadline and prioritizes sinks/authentication fields; offline batch analysis has the existing engine deadline. The optional local-artifact mode currently reconstructs website/context rules; engine-only module-split local values are outside that mode’s reconstructed coverage.

Evidence provenance is limited to 64 constituent locations and 32 transformation labels per reconstructed value. Longer chains remain unknown with semantic-provenance-budget; the scanner never silently shortens a completed reconstruction. Raw detection and other independent values continue.
