# Credential support — website/3.0.0

Version 3.0.0 (website/3.0.0) keeps every website/2.9.1 row and pattern below; no format rule was added, removed or changed. The semantic pass now follows webpack's cross-module constant exports: inside a webpack module factory it resolves the primitive exports of other factories in the same downloaded file (`exports.x =` written once, `require.d` getters, re-export getter chains, `require(id).x` reads and string concatenation across them), so a key whose parts are split across modules can be reconstructed. Factories it cannot follow soundly stay unknown, only values that crossed a module boundary are new, and the work runs under the existing semantic operation ceiling and time slice (gap `semantic-webpack-budget` when a bound is reached).

Version 2.9 (website/2.9.0) keeps every website/2.8.0 row and pattern below and adds 31 format rules for 28 further providers, from Linear to Mapbox in the table below, ported as reviewed data from Gitleaks and Nosey Parker (see THIRD_PARTY_NOTICES.md). Each rule requires a fixed prefix or a fixed structure, uses bounded repeats and refuses a match that continues past the format; generic and entropy-only upstream rules were not ported. No existing rule or finding changed.

Version 2.8 (website/2.8.0) keeps every website/2.7.0 row and pattern below; no detection rule changed. Two things changed in how analysis runs. Scans that run side by side in a mass run (`--concurrency`) share one detector and one analysis memory budget (the analysis memory setting, granted first come, first served), and each scan keeps its own cancellation and its own stated limits and failures. The wall-clock analysis limits (the isolated large-text inspection, the offline engine run, the decoded-view enumeration and the per-website analysis allocation) scale with an analysis time factor that a slower computer measures once per process (1 to 4; `EXPOSURE_ANALYSIS_TIME_FACTOR` sets 1 to 8), so a key in a large bundle is not missed only because the clock ran out first; a stated limit names the scaled time. A fast computer measures 1 and keeps the 2.7 limits. Memory limits and a scan's overall time limits never scale.

Version 2.7 (website/2.7.0) keeps every website/2.6.1 row and pattern below; only where large texts are analysed changed. A text over 128 KiB is analysed in a separate analysis process within the analysis memory setting; a whole-script analysis that would not fit the setting is skipped with a stated limit, and the window results are kept. A text over 128 KiB that is inspected in the scan process itself (browser snapshots, supplied bodies, URLs) gets window checks and embedded-script checks only, never a whole-document parse; a stated limit is shown when the same text is not also analysed in an analysis process.

Version 2.6 (website/2.6.0) changes detection in two places. Large scripts (up to 2 MiB) get one bounded whole-document parse after the format windows, so a key split across a large bundle's constants keeps its provider context. Hex strings are decoded statically when they decode entirely to printable text. Character-code calls such as `String.fromCharCode` are runtime territory: browser debugger capture sees them, static analysis does not evaluate them. The rows below were unchanged from 2.5 until the detection-quality update described next.

The detection-quality update after 2.6.0-rc.1, released in 2.6.0 as rule version website/2.6.1 (see archive/notes/HANDOFF_GITHUB_COMPARE.md, local working notes that are not packaged), adds the Docker Hub, Figma, Tailscale, Vercel AI Gateway, Firecrawl, Jina, Tavily, Google OAuth, Cloudinary, FTP / SFTP, mail server, message broker and LDAP rows, extends the Vercel, Square, Braintree, signed URL / webhook and GitHub entries, and changes four things across all rows. (1) One shared filter recognises templates and placeholders (`${VAR}`, `${{ secrets.X }}`, `{{ var }}`, `%VAR%`, `$VAR`, `<your-key>`, "your_…"/"changeme" wording, masked `****`/`xxxx` fillers and runs of one repeated character), so they never become findings; a default such as `${VAR:-literal}` is still examined. (2) JSON written with character references inside an HTML attribute (`&quot;`, `&#34;`, `&#x22;`) is decoded once as an extra view, at most 32 attributes per document within the existing view and time limits, and findings keep their original location. (3) GitHub `ghp_`/`gho_`/`ghu_`/`ghs_` tokens get an offline CRC32 checksum check: a valid checksum is noted in the reasons; a mismatch, typical of documentation examples and edited copies, keeps the finding but lowers it to review priority with the `checksum-mismatch` qualifier. (4) The SARIF export describes each rule (providers, categories, remediation help, CWE-798 or CWE-200 tag, `security-severity`, `precision`) and carries active suppressions as accepted external suppressions. Regular expressions adapted from Nosey Parker (Apache-2.0) and secretlint (MIT) are listed in THIRD_PARTY.md. References for the new rows come from the adapted rule sources or the providers' documentation entry points and were not re-reviewed online in this update.

The 2.6 scan options decide where the scanner looks, not what the detector recognizes. Every option uses the same rules.
- **Quick check** examines entry documents and their inline scripts, up to 40 referenced first-party scripts per website (entry-document bundles first), their source maps, framework build manifests, the web app manifest and referenced configuration, and the high-value deployment paths.
- **Standard** adds static discovery to depth 3, adjacent source-map checks and a few isolated-browser pages per website with debugger capture.
- **Deep audit** adds depth 5, more browser routes, query variants, all deployment paths, supplied stale assets and registrable-domain discovery, up to the hard ceilings.
- **Low-impact** keeps the coverage and changes only pacing and connection reuse. It examines one query-string variant per path, shown as "Limited by profile", and skips adjacent source-map guessing and retries.

See USER_GUIDE.md ("Ready scan options in 2.6") and the measured matrix in TEST_RESULTS.md.

Version 2.5 adds the wallet, JWK, PGP and application-signing rows below, usage-context detection (signing and encryption calls, credentials sent to unmapped hosts, unknown SDK constructors, signing-secret field names) and the `priority/1` assessment: impact rows (paid usage, cloud spending, payment/asset access, account takeover, signing/encryption, data access), qualifiers (test environment, missing secret or identifier, documentation context, published example, encrypted key material, previous deployment only) and a strictly financial `financialPriority`. Values published in vendor documentation or reference test vectors are matched by SHA-256 digest (`rules/known-public-examples.json`) and moved to the masked dismissed audit. Documentation context only lowers priority; it never hides a finding. Nothing is validated, derived or sent anywhere.

Official authentication references reviewed on 2026-10-06 (2.5 rows on 2026-10-08). Authentication documentation defines roles/components, but seldom guarantees a permanent lexical token shape. Prefix rules are bounded offline heuristics; opaque credentials require explicit provider names, configuration/SDK fields or known provider request endpoints. Bare arbitrary strings do not have universal coverage. No provider name implies complete support.

## Relationships, confidence and locations

Only literal objects, qualified variables in one lexical scope, one qualified environment paragraph, the PHP define() constants of one file or the name/value rows of one debug-page table can pair. Endpoint URLs and key identifiers beside sensitive names (token_uri, auth_url, private_key_id) are never private credentials. Separate objects are not pooled; ASIA without session token remains partial. A complete label means the detector observed its supported required components, not that authentication would succeed. Conflicting/duplicate fields remain partial. Missing account identifiers and dynamic expressions remain visible limitations of inference.

Bounded percent/Base64/hex/escape decoding, static literal concatenation and const references retain original source representations and transformation steps (hex only when it decodes entirely to printable text). Values built by function calls such as String.fromCharCode are left to browser debugger capture. Texts over 128 KiB are inspected in overlapping 64 KiB windows; scripts up to 2 MiB are also parsed once so provider context (enclosing object, scope and call) is kept for subtrees that name credentials, providers or signing sinks. Expressions/target functions are never evaluated. RE2 custom rules reject executable patterns. Generic entropy is contextual evidence, not proof; placeholders, UUIDs and content hashes are negative controls. Locations use UTF-16 source indices internally with line/column/byte evidence; source maps label extracted coordinates and mapped-segment precision. Runtime snapshots have no invented source line.

Technical severity does not decrease because an exposure falls outside financial categories. Financial urgency requires credible private evidence, with sandbox/test priority separated and unknown environment stated. Impact uses potential wording. No permission, balance, working-access or guaranteed-loss claim is made.

## Coverage limits

Supported text: HTML/comments, referenced scripts/lazy modules, CSS, JSON/config, static framework manifests/hydration, public API responses, source maps/embedded sources and bounded fresh browser DOM/config/storage. Version 2.4 adds offset-preserving TypeScript syntax erasure, constants surrounding unknown JSX markup, downloaded virtual source-map imports, SDK aliases, computed keys, and dedicated-worker/separate-frame debugger descendants. See docs/history/UPGRADE_2.4.md for exact limits and unsupported mutation/runtime constructs. Structural exposure checks recognize supported password hashes in password fields, sensitive JSON fields with owner expectations, private configuration and detailed debug stacks; intended audience remains subject to owner review. Binary fonts are intentionally skipped; disguised UTF-8 configuration is inspected. Encrypted archives, images/OCR, arbitrary computed URLs, executable obfuscation, authenticated areas and undiscovered code are unsupported. Parse limits, runtime size/depth/count limits and inaccessible referenced sources remain gaps. Finite deployment probes need content confirmation; SPA/login/fallback responses do not establish a published file. Adjacent map guesses returning 404/non-map are observations.

One scope policy (exact approved origins plus, in domain scope, admitted subdomains of the entered domains), DNS/socket/TLS/redirect checks and the deny-only proxy remain. No online token validation, authentication, financial operations or provider calls using a detected value. Suspected outgoing private URL/header/body material is inspected and blocked locally, including supported encodings. Unknown Authorization/API-key headers fail closed. Ordinary requests remain observable.

Current results are in benchmarks/results.json (per fixture and detector) and benchmarks/pipeline-results.json (full scanner/browser stages). The machine-readable coverage-registry.json links supported formats, provenance, limits and fixture IDs. It does not claim universal coverage.
