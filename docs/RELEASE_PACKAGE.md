# Exposure Desk 3.0.0 delivery

3.0.0 follows 2.9.1. The Windows x64 and Source ZIPs and the Linux x64 package are in `artifacts`, with `SHA256SUMS-3.0.0.txt` (all three packages), `release-3.0.0-results.json`, `final-parity-3.0.0.json` and `ARCHIVE_INDEX.json` (2.4.0-rc.1, 2.5.0-rc.1, 2.6.0-rc.1, 2.6.0, 2.7.0, 2.8.0, 2.9.0 and 2.9.1 superseded but kept unchanged, 3.0.0 current). GitHub Actions could not run for this release (the account's billing blocks every workflow), so the jobs of `linux.yml` were reproduced on a rented Ubuntu 24.04 server from the same build: the Linux x64 package, `Exposure Desk 3.0.0 Linux x64.tar.gz` with its `.sha256`, was built there by `scripts/package-linux.mjs`, checked with `sha256sum --check` and the packaged smoke test, copied to `artifacts` and checked against its `.sha256` file again; the container image was built from `docker/Dockerfile` and passed `scripts/docker-smoke.mjs` there, and was not pushed to any registry. The commands, the package SHA-256 and the results are in `benchmarks/3.0.0/linux-server.json`. The three packages and `SHA256SUMS-3.0.0.txt` are attached to the GitHub Release `v3.0.0` of this private repository, the Linux package under the fixed asset names `exposure-desk-linux-x64.tar.gz` and `.sha256` so that `gh release download v3.0.0 --pattern '*.tar.gz*' --dir artifacts` followed by `node scripts/linux-release-assets.mjs --dir artifacts` restores it as before; GitHub replaces the spaces in the ZIP names with dots. From 2.6.0 on, release records carry the full version in their names; the records of 2.6.0-rc.1 and earlier keep their original names (`SHA256SUMS-2.6.txt`, `release-2.6-results.json`, `benchmarks/2.6/`) and were not rewritten. The final build identity is in BUILD_INFO.json and PACKAGE_MANIFEST.json; measured checks are in TEST_RESULTS.md, with the raw records in `benchmarks/3.0.0/`.

**Linux package from 2.9.1 on.** linux.yml no longer stores the Linux package as a workflow artifact by default. A manual run with a release tag attaches it to a **draft** GitHub Release of this private repository (`gh workflow run linux.yml --ref <branch> -f release_tag=v<version>`), after `sha256sum --check` and the packaged smoke test have passed. Release assets do not count against the Actions artifact storage quota. The draft is created if missing, and the two assets (`exposure-desk-linux-x64.tar.gz` and its `.sha256`) are replaced with `--clobber` on each run for the same tag. The job summary records the run, commit and SHA-256. The workflow never publishes the release and never deletes releases, assets or artifacts; a draft creates no git tag. Pull requests and plain runs build and check the package but upload nothing. To fetch it, run `gh release download v<version> --pattern '*.tar.gz*' --dir artifacts` and then `node scripts/linux-release-assets.mjs --dir artifacts`. The script checks the package against its `.sha256` file and the version, then gives both files back their package names (`Exposure Desk <version> Linux x64.tar.gz`), so `sha256sum --check` and `release-summary.mjs --after-package` use them as before. See docs/LINUX.md. For 3.0.0 the workflow could not run, and the package built on the server was attached under the same asset names instead.

Before switching, stop every running instance and back up the whole data directory shown in Settings, and every `--program` folder. On Windows, extract the Windows x64 ZIP into its own folder, double-click Start Exposure Desk.cmd and enter the printed token in the local dashboard. On Linux, check the package with `sha256sum --check`, extract it with `tar -xzf` and run `Start Exposure Desk.sh` (see docs/LINUX.md; Chromium needs some system libraries, and the launcher never installs anything). The container image is built with `docker build --tag exposure-desk .` from a checkout of the repository and run as docs/LINUX.md shows; the dashboard listens only on `127.0.0.1`, so use `--network host` on a Linux host. 3.0.0 reuses the 2.9 data directory in place and needs no migration: every 2.9 flag, configuration file, program file, checkpoint and saved record keeps working, and JSON Lines stays `exposure-jsonl/1` with additive fields only (see MIGRATION_3.0.md). Going back to 2.9.1 with data written by 3.0.0 was not tested; restore the backup instead. New scans still offer six ready options with Standard + Normal recommended. Exposure Desk never contacts government, military or law-enforcement websites, and nothing can override that. Compared with 2.9.1, 3.0.0 adds AWS to the opt-in live key check (STS `GetCallerIdentity`, signed with Signature Version 4 so the secret access key is never sent; the egress allowlist grew by exactly `sts.amazonaws.com`) and probes a larger high-value deployment-path set in every coverage, with a fuller curated set for Standard and Deep (rules `website/3.0.0`; the detector's rule catalogue is identical to 2.9.1). See CHANGELOG_3.0.md; the ready options and their limits, Low-impact traffic, the protected-host and authorization rules, the live key check doctrine, masking and the dashboard security model are unchanged.

The Windows x64 package reuses the supplied Node 24.18.1, locked dependencies, Gitleaks 8.30.1 and Chrome for Testing 153.0.8010.12. The Linux x64 package holds the official linux-x64 build of Node 24.18.1, the Chrome for Testing build Playwright 1.63.0 uses, Gitleaks 8.30.1 and the same locked dependencies (see docs/LINUX.md). All packages ship the BIP-39 English wordlist (MIT) and rules adapted from Nosey Parker (Apache-2.0), secretlint (MIT) and Gitleaks (MIT) with their licence files (see THIRD_PARTY.md and THIRD_PARTY_NOTICES.md). 2.6, 2.7, 2.8, 2.9 and 3.0 add no npm dependencies. The ZIPs and the Linux x64 package include LICENSE, PRIVACY.md, SECURITY.md, ACCEPTABLE_USE.md, THIRD_PARTY.md, THIRD_PARTY_NOTICES.md, DEMO.md and the dashboard screenshots. The Source ZIP omits runtimes and dependencies. Windows x64 is verified on one computer; Linux x64 was tested on one Ubuntu 24.04 server (3.0.0) and on GitHub-hosted Ubuntu runners (2.8.0 to 2.9.1). Other Linux distributions, macOS, ARM and an uninstalled source bootstrap remain unverified.

Packaging excludes operator data, tokens, private caches, full-secret exports, verification logs, the external-site recheck helper, the external review and detection corpus, internal working notes (`archive/notes/`) and temporary extracted verification copies. Checksums establish local integrity and parity, not publisher signatures; the packages are not code-signed.

**What the results mean.** Every result for 3.0.0 comes from local loopback fixtures and synthetic, nonfunctional keys; the live key check, including the new AWS recipe, was tested only against loopback stand-ins for the providers, and no real provider endpoint was contacted. The Windows timing figures come from one Windows x64 laptop. The Linux x64 test suites, package, container image and ready-option matrix ran on one rented Ubuntu 24.04 server shared with other jobs, so its timings are noisy and are compared only with the 2.9.1 baseline built and measured on the same server. No real website was scanned, so the results do not establish coverage, accuracy or speed on real websites. The legacy evaluation, the target lists at scale and the external synthetic corpus were not measured again for 3.0.0; TEST_RESULTS.md shows which 2.9.1 records are carried over.
