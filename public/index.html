What the websites can see
  • Requests come directly from this computer: sites see its public IP address, or the exit address of a system-wide full-tunnel VPN. Windows/PAC proxies, browser-extension VPNs and HTTP(S)_PROXY variables are not used, and there is no proxy option in this release. Target DNS lookups use this computer’s resolver.
  • Static requests carry an honest product token Mozilla/5.0 (compatible; ExposureDesk/2.9) (no build, OS or user details) and the configured language. Browser requests keep the bundled Chromium’s real User-Agent and use the configured language and time zone, never this computer’s.
  • Referer is reduced to the origin and sent only from authorized pages; cookies exist only for this visit, are kept host-only and are sent only from a page of their own origin.
  • No dashboard token, local path, username, project or run ID is ever sent. Sites can still tell an automated visit apart by timing, TLS and HTTP characteristics; the scanner is not undetectable.

        Application data and retention
        Deletion removes local history and encrypted evidence. No reports or vaults are uploaded.
        Optional encrypted evidence vault
        Full values stay in process memory by default. Enable only to review deliberately saved evidence after restarting.
        Local schedules and deployment triggers
        Schedules run only while Exposure Desk is open. Missed runs are recorded and rescheduled. No service or startup task is installed. A deployment trigger lets a build step request a scan of an opted-in project by running cli.js trigger --project <id> on this computer; requests are files in the protected data folder (no network listener), rate limited, and never save evidence. For a pre-deploy gate, run cli.js artifacts --directory <build>, which makes no requests.
